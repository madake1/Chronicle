# Chronicle

在同一张历史时间轴上比较游戏、小说、电影和电视剧的故事年代。

## 本地运行

需要 Node.js 20.19 或更新版本。首次克隆或更新依赖后，先安装依赖。

```sh
npm ci
npm start
```

默认打开 http://127.0.0.1:4173 。实际地址以终端打印的 `Chronicle · http://127.0.0.1:端口` 为准。

如果看到 `EADDRINUSE`，说明默认端口已被占用。在 PowerShell 里可以用另一个端口启动：

```powershell
$env:PORT = '4174'
npm start
```

这时打开 http://127.0.0.1:4174 。如果新页面空白或缺少功能，请确认地址栏与终端打印的地址一致。两个端口上的 Chronicle 实例会使用同一份本地资料库，请只用一个实例编辑。

本地资料库尚未创建时，页面会显示六部可编辑的示例作品。

## 历史时空地图

首次使用地图时先运行 `npm run atlas:prepare`，下载并生成本地数据，再启动服务。在导航点击「历史时空」，拖动滑块或输入年份，即可浏览公元前 3400 年至公元 2024 年。可用「放大时间轴」缩小浏览范围，也可按中英文名称或别名搜索政权。当前年份有匹配记录就直接定位，否则可在结果中选择疆界资料年代。数据准备好后可断网浏览。

生成文件及下载的原始数据在 Git 忽略的 `atlas-data/`。地图标注了 Cliopatria v0.2.1（CC BY 4.0）和 Natural Earth v5.1.2 1:110m（公有领域）的来源。底图只使用自然地理图层。

政权搜索和卡片共用名称索引，候选词来自完整疆界数据的原名、Wikipedia 标题、已有中文名称及 `atlas-polity-aliases.json`。百科链接优先使用已核实的中文词条，其次是英文词条。更新名称后运行 `npm run atlas:prepare` 生成索引，原始数据已缓存时无需联网。

展开政权卡片的「历史疆域演变」可查看已关联的疆界记录和估算面积，也可跳转到记录适用的年份并高亮疆界。从旧版升级时，重新运行 `npm run atlas:prepare` 生成 V3 年份索引和几何分块，再重启服务。原始数据已缓存时无需联网。

V3.5 加入 Natural Earth v5.1.2 的 1:110m、1:50m、1:10m 自然地理图层和一组北宋历史地点。升级后先运行 `npm run atlas:prepare` 下载并处理自然地理数据，再重启服务。输入 1066 年并放大到中国中原区域，点击汴京、洛阳或大名府可查看收录年代、当时的都城身份和出处。位置为近似点位，海岸线、湖泊、河流和山地区域为现代地理参考。地图放大后才加载高精度数据。

- 在绘图区域滚轮缩放，拖动空白处平移。点作品名称或标记查看详情。
- 短跨度在全景中用菱形表示，放大后恢复为按时间比例绘制的线段。
- 年份支持 `1191`、`公元前431`、`-431`。一个作品可填写多段。不填时间段时归为年代未知。
- 保存后，资料库写入 `data/chronicle.json`。可在停服后复制这个文件备份，Git 默认忽略该目录。

## 作品笔记

作品库是首页。每部作品都可打开独立 Markdown 笔记，即使年代未知也能创建。已有的简评和参考链接仍可在作品详情中查看。

- 在作品库点击「创建笔记」或「查看笔记」。编辑时可插入 PNG、JPEG、GIF 或 WebP，每张限 8 MB。整理笔记时可以移除图片引用，已上传的图片文件仍保留在该作品的素材目录。
- 保存后可以导出 Markdown 正文或包含正文和引用图片的 ZIP。解压 ZIP 后，从根目录打开 `note.md` 即可按原相对路径查看图片。
- 作品库的「批量导出笔记」每页列出 10 部已保存笔记的作品，可跨页勾选或全选所有页。导出的 ZIP 为每部作品创建独立目录，图片仍可通过原相对路径查看。
- 笔记与素材位于 `data/works/work-<id>/`。备份或换机时，停止服务后复制整个 `data/`，这样可一起保留索引、笔记和图片。

```sh
npm test
```

V3.6 补齐北宋四京试验地点。地点卡片分别显示有资料支持的收录时段、历史名称和都城身份。点位为近似位置，收录时段只描述本项目采用的资料范围。首批采用独立整理的事实与近似坐标，出处见卡片，未打包 WHG 或 CHGIS 数据。

V3.7 提供 Historical Basemaps 对照模式。可选运行 `npm run atlas:prepare -- --with-comparison`，将固定上游版本的公元前 2000 年、前 500 年和公元 1200 年快照及许可证保存到本地 `atlas-data/`。重启后在「地图资料来源」选择对照快照，地图保持原视角。快照只代表标注的年份，前 2000 年的夏朝为上游历史重建示意。快照由用户直接从上游下载，项目仓库不分发这些文件。下载完成后可离线使用。

V3.8 增加全球历史地点试点和独立的「搜索地点」。升级时运行 `npm run atlas:places` 并重启服务。此命令只读取仓库的小型来源文件并生成本地索引，也会随 `npm run atlas:prepare` 执行。试点包括 Pleiades 地中海城市、北宋四京、先秦与汉唐城址、中世纪欧洲、大津巴布韦、平安京和近现代城市。索引使用来源明确的收录窗口，窗口外不会自动显示。地点卡片可查看其他历史名称及其适用年代。WHG 本轮未导入。

### 批量导入历史地点

先从 Pleiades 官方下载完整 JSON 压缩文件。导入读取本地文件，不会联网：

```powershell
npm run atlas:import-places -- pleiades "D:/downloads/pleiades-places-latest.json.gz"
```

WHG 使用发布者原始的 LPF JSON，不导入 WHG 另行许可的对齐链接或编辑文本。确认子集许可后，将其元数据和本地文件交给同一导入命令。下面以 Medieval Swahili Coast 为例：

```powershell
npm run atlas:import-places -- lpf "D:/downloads/medieval-swahili.json" atlas-places/whg-swahili.example.json
```

导入生成版本校验值，并把原始数据包衍生结果存在 Git 忽略的 `atlas-data/place-packs/`。运行 `npm run atlas:places` 可离线重建查询索引。已核实的 18 个地点优先，明确对齐的外部条目保留原始来源和地名资料。地图使用有明确地点记载的时段，其他地点只参与搜索。地点记载、存在年代、地名和历史身份分别保存。

新版页面通过 Node.js 按年份、地图视野和缩放请求地点。批量导入或重建索引后重启服务，载入新索引。地点搜索和详情也走本地 API。
