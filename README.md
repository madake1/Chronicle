# Chronicle

用时间轴和离线历史地图探索世界历史的个人学习项目。可记录游戏、小说和影视作品的故事年代，也可独立查看政权疆界、历史地点和现代地理参照。

## 已有功能

- 作品库、个人时空、Markdown 作品笔记、插图与单份或批量导出。
- 知识库支持快速写 Markdown、按层级标签浏览、标题与正文搜索，以及关联其他知识、作品和作品笔记。
- 历史地图支持公元前 3400 年至公元 2024 年、政权名称和别名搜索、疆域演变、百科链接。
- 历史地点按年份和视野加载，可搜索并查看名称、史料和出处。没有可靠年代的地点可搜索和定位。
- V4 历史事件随地图年份显示，可按类别和关键词筛选，查看简介、点位和出处。
- Cliopatria 自由年份地图和 Historical Basemaps 固定快照可切换。海岸线、河流和山地标为现代参照。

## Windows 便携版

解压 Windows x64 程序包到可写目录，双击 `Start-Chronicle.bat`。启动器会验证本机实例，等服务就绪后打开默认浏览器。再次双击会打开正在运行的同一资料库。双击 `Stop-Chronicle.bat` 等待服务写入完成并退出。关浏览器标签页不会停止服务。

程序包内置 Node.js，启动不需要系统 Node.js、npm、Git 或联网。全新解压第一次启动会显式建立空的 `data/`。示例需使用下方的独立开发模式。默认目录安排如下。

| 目录或文件 | 用途 |
| --- | --- |
| `app/`、`runtime/` | 程序、生产依赖、Node.js |
| `data/` | 正式资料库，包括知识、作品、Markdown 和附件 |
| `atlas-data/` | 单独准备或恢复的历史资料 |
| `logs/` | 本地日志、启动记录和实例状态 |
| `version.json` | 源码提交、运行时版本和运行时校验摘要 |

如需使用已有资料或固定其他端口，可在便携目录根创建 `chronicle.config.json`。相对路径以便携目录为基准，也可填写绝对路径。Windows JSON 路径可使用正斜杠。指向已有正式库时，先停止旧实例并核对备份，文件缺失时先恢复。示例配置如下。

```json
{ "port": 4173, "dataDir": "data", "atlasDir": "atlas-data" }
```

全新安装使用默认配置即可。显式设置 `dataDir` 时要求该库已存在。遭遇端口占用或已有库缺失、损坏时，检查 `logs/chronicle.log`。如果已存知识正文仍在但知识索引丢失，服务会拒绝启动，需从同一份备份恢复资料。已知为老版本启动的 Chronicle 需要用其原来的方式关闭。只有已验证身份的便携实例可以用便携停止入口关闭。缺少历史资料时仍可使用作品库和知识库，按 [数据源清单](docs/DATA_SOURCES.md) 在开发机准备资料后单独复制或恢复至 `atlas-data/`。

### 构建、升级和恢复

开发机在项目根目录执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-portable.ps1 -Ref HEAD`。构建需要 Git、Node.js/npm 和网络，从指定 Git 提交归档程序文件、用锁文件安装生产依赖，输出版本化目录、ZIP 及 ZIP 的 SHA-256 到 `dist/`。程序包只支持 Windows x64，内置官方 Node.js 24.22.3。构建脚本按固定 SHA-256 核验下载，并保留 Node.js 的许可。程序包不包含个人库、日志、凭据或单独准备的地图资料。

升级前双击停止，等待确认后备份完整资料目录、配置、BAT 入口和版本文件，记录清单与 SHA-256。将新版先解压到另一个空目录，将原安装的 `app/` 和 `runtime/` 改名留存，再从新包复制同名目录、BAT 入口和 `version.json`。保留 `data/`、`atlas-data/`、`logs/` 和配置。若启动失败，关闭新版后把保留的旧程序、运行时和入口恢复原名。数据库缺失或损坏时，先将当前资料另存，再恢复同一快照的整份资料库。保留原始资料与校验记录。

## 源码开发和示例

需要 Node.js 20.19 或更新版本。首次准备地图时需要网络。

```powershell
npm ci
npm run atlas:prepare
npm start
```

开发模式默认使用 Git 忽略的 `.chronicle-dev/development/` 空库。显式演示使用 `CHRONICLE_MODE=demo` 与 `CHRONICLE_INIT=1`，首次初始化 `.chronicle-dev/demo/` 时写入示例，后续沿用该独立库。正式模式使用 `CHRONICLE_MODE=formal` 和绝对路径 `CHRONICLE_DATA_DIR`。可通过 `CHRONICLE_ATLAS_DIR` 指定绝对历史资料路径。测试使用临时目录。

默认服务是 [http://127.0.0.1:4173](http://127.0.0.1:4173/)，历史地图在 `/atlas`。若设置了 `PORT`，以终端显示地址为准。需要对照快照时，首次运行 `npm run atlas:prepare -- --with-comparison`。

作品和知识库保存在 `data/`。建议停止服务后备份整个目录。地图和外部地点的本地文件在 `atlas-data/`，新装时需按 [数据源清单](docs/DATA_SOURCES.md) 恢复或导入已有资料包。已准备的数据可离线使用。

## 使用个人时空

从顶部打开「个人时空」，在时间轴、地图和时空联动之间切换。旧地址 `/?page=timeline` 会打开个人时空。作品详情的「定位」和时空中的「打开原条目」可以往返查看。作品和知识用不同颜色，选中一个标注会突出显示对应的时间段或地图点。同坐标的标注可展开选择。计数分别显示原条目和标注数量。

默认加载作品图层，勾选「知识」时才读取个人知识标注。两种图层可分别开关，知识位于独立的时间轴泳道。缩放时重新排布卡片，密集处点击数量可展开或进一步放大。时间轴支持横向拖动、Ctrl + 滚轮及键盘方向键与 ＋/−，常规滚轮用来滚动页面。地图按当前缩放聚合相邻点位，可用「适配点位」查看整组结果。顶部四个入口及主题设置在各页共享。

从作品详情编辑时空片段，或在知识编辑器展开可选的「时空标注」。可以只写年代、只写地名或只填坐标。同一标注中的年代和地点描述同一个片段。填写完整经纬度或用地图选点后才会上图。仅有地名的标注保留在原条目。知识可以继续无标题、无标签地直接保存正文。

年份输入示例为「公元前 1 年」或「1200」。年份快照匹配所选年，年代区间匹配任一重叠年份，均含端点。累计分布显示截至该年曾涉及的内容。虚线标识不确定年份或可能发生范围。年代未知点在独立区域列出，开启时间筛选后需要显式选中「年代未知」才显示。作品类型只限制作品，知识标签只限制知识且包括后代。启用「仅当前视野」后排除无坐标的标注。

地图底图参考年可单独输入。超出覆盖或缺少历史资料时，保留个人坐标及可用地理参照。历史时空继续从独立的 `/atlas` 浏览。

## 使用知识库

从顶部进入「知识库」，点「记录知识」即可直接写正文。知识条目的标题可空，标签和关联可在编辑器里按需展开，也可以保存后再补。列表按记录时间倒序，搜索匹配标题、正文和标签，可和标签筛选叠加。点上级标签会汇总下级的知识并去重，标签名旁的展开按钮单独控制树的显示。移动端可打开「标签索引」查看标签。

「管理标签」可搜索并直接操作标签树。数量包含后代并去重。删除标签时，直接关联的知识继承该标签的父级，直属子标签同步上移。删除顶级标签时，移除该标签后没有其他标签的知识进入「无标签知识」。提升子标签若出现同级重名，需要先重命名或移动相关标签。

打开知识条目可预览或跳转到关联条目。作品详情的「关联知识」区可添加或移除关联、展开正文或跳转阅读，作品笔记仍可通过「关联知识」反查。作品与历史时空的原有资料格式无需迁移。

## 架构

Node.js HTTP 服务 + 原生 HTML、CSS 和 ES Modules + MapLibre GL JS。作品、地图和知识元数据使用独立的 JSON 索引，作品笔记和知识正文使用 Markdown，附件存放在本机。

| 目录 | 用途 |
|---|---|
| `public/` | 作品库、时间轴、知识库和历史地图前端 |
| `scripts/` | 下载底图、预处理疆界、导入地点、生成本地索引 |
| `atlas-places/` | 小型来源记录和导入元数据 |
| `atlas-data/` | 本地原始地图数据、地点包和生成索引，Git 忽略 |
| `data/` | 个人作品、作品笔记、知识条目和附件，Git 忽略 |

## 数据与维护

已接入 Cliopatria、Natural Earth、Historical Basemaps、Pleiades、WHG、日本 CODH、Viabundus、Reba 等的全球历史城市，以及 Wikipedia/Wikidata 名称关联。可搜索 GeoNames 全球现代城市和首都作为地理参照。历史覆盖随地区和年代变化，中国古代地名仍稀疏。

开发接手请先读 [数据源清单](docs/DATA_SOURCES.md) 和 [交接说明](docs/HANDOFF.md)，再检查实际工作区。测试运行 `npm test`。
