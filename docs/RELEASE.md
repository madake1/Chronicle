# Chronicle 正式发行

首个正式安装版本为 V7.1.0，标签为 `v7.1.0`。程序固定在 `3259af65fa0f994fc8cf97548fbe87336bfbf0f4`，含作品、知识、标签和个人时空。发行 ZIP 的 SHA-256 为 `4338b3a3c3b78d2e708d94e29cfe37b2e05620b753befb409a92dca443f193ca`。首装使用独立空库。

## 晋升与构建

1. 在 `codex/*` 开发，经 PR 验收后合入 `main`。发行从 `main` 选择固定提交，经候选验收和用户批准后推进 `release`。紧急修复走独立分支和 PR，并同步回 `main`。
2. 使用独立检出执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-portable.ps1 -Ref <完整提交 SHA>`。保留 ZIP、SHA-256、包内 `version.json` 和验收记录。解压前以 `Get-FileHash -Algorithm SHA256` 核对 ZIP。
3. 先在隔离库验证 Windows 批处理入口、重复启动、不同资料库并行写入、同库拒绝、重启持久化、快照恢复及浏览器主要流程。记录使用的历史数据范围。确认候选后再给已验证提交打标签。发行包仅含程序及依赖。
4. 正式实例使用固定包。开发拉取、切分支、运行测试与正式升级相互独立。V8 晋升前，用合成 V7.1 库验证原 ID、正文、附件、标签、关系、时空标注和旧文件保留，确认空专题能引用原有知识。

## 安装与本机使用

正式安装使用工作区外的目录。将包解压到独立程序目录，资料目录、历史资料目录及备份目录各自独立。通过程序目录中的 `chronicle.config.json` 指定绝对路径和专用端口：

```json
{ "port": 4180, "dataDir": "D:/Example/Library", "atlasDir": "D:/Example/Atlas" }
```

新建外部库时，先在全新程序目录省略 `dataDir`，用启动入口初始化默认空库，停止后将完整空库放入约定的新目录，再配置绝对路径。已有库接入前先确认原路径并停止旧实例，制作并校验完整快照，保留原库，取得授权后再接入。显式指定的目录缺失时，启动器会报错。

双击 `Start-Chronicle.bat` 打开正式实例，再次双击复用已验证实例。双击 `Stop-Chronicle.bat` 并等待停止完成。关闭浏览器标签页后服务继续运行。

## 备份、升级与回滚

1. 停止实例，将完整资料目录、配置和版本记录复制到新快照目录，生成文件清单及 SHA-256 并逐项校验。保留匹配的旧程序包和校验值。历史资料按来源和版本独立备份。
2. 将新版解压到其他目录，复制所需配置，保留旧安装、资料、历史资料和日志。升级后检查作品、知识、附件、标签、关联和时空，再恢复日常写入。
3. 升级失败先停止新版，将当前资料另存并校验。把升级前的完整资料快照还原到新目录，用匹配的旧版本及配置启动并验证。升级后新增的记录留在另存的新版资料中，需要另行处理。旧版写入新版库的兼容性需单独验证。
4. 知识删除目前没有回收站。恢复依赖删除前的资料快照及其配套文件，整库恢复会回到快照时点。
