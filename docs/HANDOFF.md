# 开发交接

接手顺序：README → DATA_SOURCES → 本文 → `git status -sb` → 核对本地文件与端口。忽略目录可能因机器而异。不要假设已下载或生成的数据随 Git 同步。

## 目标和约束

以历史年代为坐标浏览作品与地图。数据应能离线读取、可追溯并保留原始标识。疆界有效期、地点记载、地名和历史身份各自有语义。资料缺失应保留空值或仅搜索。不同来源的同名、近邻地点不自动合并。

## 关键位置

- `server.mjs` 负责 HTTP、静态资源和路由。作品库由 `public/app.mjs` 驱动，个人时空由 `public/spacetime.mjs` 驱动，年代计算在 `public/chronology.mjs`，体验日期规则在前后端共用的 `public/experience.mjs`。历史时空是独立的 `/atlas` 页面，地点和事件查询分别由 `atlas-place-index.mjs` 和 `atlas-event-catalog.mjs` 处理。
- `public/atlas/atlas.mjs` 控制时间和来源；`geography.mjs` 负责地图地点标签与卡片；`place-api.mjs` 负责本地请求去重与缓存。
- `public/atlas/events.json` 保留原始事件，另外加载 `events-wikidata.json`、`events-noaa.json`、`events-milestones.json`。`event-data.mjs` 校验及筛选，`events.mjs` 管理列表、标记及详情。`scripts/import-noaa-events.mjs` 将 HazEL JSON 按审定名单生成可离线分发的样本。对照模式使用实际快照年份，地点关联沿用原有详情 API。
- `scripts/prepare-atlas.mjs` 生成背景、疆界、对照和地点索引；`scripts/import-places.mjs` 和 `import-place-data.mjs` 负责 Pleiades / LPF。
- `scripts/prepare-codh-poi.py` 与 `scripts/prepare-viabundus.py` 将外部 CSV 转为 LPF。
- `atlas-data/raw/` 原始文件，`atlas-data/place-packs/` 归一化来源包，`atlas-data/place-query-index.json` 服务查询索引。
- `atlas-encyclopedia.json` 为仓库中的核对快照，`atlas-polity-aliases.json` 为人工别名。
- `data/` 是用户资料，维护地图时避免修改。

| `note-files.mjs` | Markdown 渲染和本地图片引用解析、图片类型检查和读写。渲染由调用方指定图片 API 前缀，原始 HTML 禁用，图片仅解析为当前笔记的本地资源。 |
| `note-storage.mjs`、`server.mjs` | 由作品 ID 定位笔记，核对作品关系和正文版本，组织单份与批量导出。作品 API 继续使用 `/api/works/:id/note`。 |

## 架构审计结论

- **前端继续使用原生 ES Modules。** 当前作品和地图已有页面边界，笔记复用只需要实例化对话框并提供 API 基址。等多个页面实际出现复杂的共享状态、组合式编辑或重复渲染逻辑，再以具体维护成本评估框架。
- **继续使用 JSON 索引、Markdown 正文和独立图片。** 当前以本地单用户运行，正文便于备份、直接读取和导出。先按实际笔记规模评估列表与搜索；出现文件扫描或整表写入瓶颈、明确需要全文索引或多条元数据事务时，再评估 SQLite。可先让 SQLite 承载可重建的索引；跨数据库和文件的原子性仍需单独设计。
- **作品整表保存使用版本校验。** V7 在共享队列内校验 If-Match，拒绝过期列表并保留最新的笔记路径。逐条保存属于后续独立评估。
- **笔记索引、正文和图片有各自的写入时机。** 首次保存先写正文再写作品索引；进程在两次写入之间中断可留下未关联正文。放弃含新图片的草稿或删除作品也可能留下文件。以后增加检查或恢复路径时，先定义恢复规则和测试中断场景，再处理无引用文件。
- **ZIP 在内存中生成。** 当前沿用 128 MB 内容上限。大量图片的知识条目有了可测量的导出需求之后，再考虑流式打包。

本轮回归通过 28 项自动化测试，包括笔记版本冲突、图片上传与读取、作品索引绑定和单份及批量导出。作品库列表提供查看或创建笔记的入口。

## V5 知识库

知识页入口是 `/knowledge`，后端路由和关联服务在 `knowledge.mjs`。知识条目和作品笔记各自维护 API、索引、文件和生命周期，并共用编辑器、Markdown 渲染、图片校验和 ZIP 文件组织。共享编辑器的业务名称和无标题导出名由调用方提供。作品及作品笔记分别使用 `work:<id>` 和 `work-note:<id>`，知识使用 `knowledge:<id>`。作品笔记以现有作品 ID 标识，现有路径无需迁移。历史时空保持独立。

知识元数据、标签和关联存于 `data/knowledge/index.json`。关系两端排序后只存一条，双向读取同一条记录。标签用稳定 ID 引用，移动和重命名仅更新标签记录。删除标签、提升直属子级、迁移直接关联在一次索引替换中完成。非顶级标签的直接关联继承父级并去重，顶级标签的直接关联只移除该标签。只关联后代的知识保持原标签。提升遇到同级重名会中止整次删除。管理面板在 `public/tag-manager.mjs`。元数据有独立的乐观版本检查，防止旧编辑页覆盖反向新增的关系。

知识首页的标签计数包含后代并去重，正文、标题和标签路径参与搜索，结果按创建时间倒序。已展开的知识退出当前结果时，详情关闭并清除 URL 的 `note` 参数。外部直达链接仍可打开详情。公共编辑器在知识页可提交可选元数据，服务内一次提交正文版本、标签及关联。标签重命名只提交 `name`，移动只提交 `parentId`。服务在写入队列内读取并保留未提交字段。关联选择通过 `/api/knowledge/targets?q=` 在服务端匹配标题和知识正文，只传回标题或最多 120 字符的摘要。作品详情的关联区使用 `/api/knowledge/works/:id` 查询，单条关系使用 `/api/knowledge/works/:id/:noteId` 幂等添加或移除。

知识正文使用 `data/knowledge/note-<id>/<sha256>.md`，图片在同级 `assets/`。写入先落盘正文，再原子替换索引。中断时旧索引仍指向旧正文。删除知识时原子移除索引条目及两端关系，正文和附件留在磁盘并从页面及 API 隐藏。当前没有回收站或单条恢复入口，恢复完整条目需要删除前的索引和配套文件。作品或作品笔记删除先提交作品索引，再清理关系，启动时按现有作品索引重试清理。查询过滤失效端点。备份或还原时应停止服务，并将同一快照的整个 `data/` 一起复制。未引用的正文版本、草稿附件和已删除知识文件暂保留，自动回收属于后续技术债。

V5 沿用 Node.js 20.19 运行要求，以原子替换 JSON 索引保证知识元数据更新的一致性。全文搜索扫描 Markdown，适用于本机小型资料库。需要更大规模搜索时可评估 SQLite 索引，文件与索引的恢复边界仍需保留。

## V7 个人时空

- 作品标注扩展原 `segments`，保留年代、顺序、置信度和来源。知识标注存于 `knowledge/index.json` 的原条目中。内部年 0 表示公元前 1 年，公元后 1 年是内部年 1。只填地名的标注可以保存。没有明确坐标时不做地理编码。
- `GET /api/spacetime` 在共享写入队列中获取两份索引的一次快照，再生成按标注展开的读模型。浏览器按关键字、类型、标签后代、年代和地图视野组合筛选。稳定标识由原实体 ID 和标注 ID 组成。视图无持久化索引，删除归属记录后下次投影自动消失。页面聚焦或从浏览器缓存返回时刷新，以请求序号防止旧响应覆盖。
- 作品旧片段读取时以内容指纹生成可重现 ID，重复片段按相同内容的出现次数消歧。带版本的作品保存将 ID 与片段一起原子提交。启动和读取均不改写旧资料。备份和恢复仍使用完整 `data/`。
- `GET /api/works?annotations=1` 返回带标注 ID 的作品和作品索引 ETag。作品编辑通过整表 PUT 的 `If-Match` 校验同一索引版本，冲突返回 409。旧整表写入兼容未进入版本化编辑的旧库。首次版本化保存后，索引本身记录该状态，之后旧的无版本请求会返回 409，即使已有标注全部删完。知识通过原元数据版本保护标注，省略标注字段会保留已有值。
- `public/spacetime.mjs` 使用本地 MapLibre 与历史时空既有的疆界快照读取器。个人点位、筛选范围及底图参考年分别处理，范围外与缺资料时可保留点位。`/atlas` 的地点和事件服务独立运行。暂未增加历史地点搜索或引用编辑。

## V7.1 界面与查询

- `public/app-shell.mjs` 为四个顶级页面生成导航，按路径标记当前页，并共享 `chronicle-theme`。四页的样式和模块均由服务端白名单提供，整个 `public/` 已包含在便携构建归档中。旧时间轴 DOM 与绘制已移除。旧 `/?page=timeline` 继续跳转个人时空，带 `note=1` 的作品笔记深链保留作品库处理。
- `GET /api/spacetime?layer=work` 不读取知识索引，`layer=knowledge` 只投影知识标注与标签，`layer=both` 和无参请求兼容完整结果。界面只查询启用的层，关闭会终止该层的旧请求并清空投影。聚焦时重新读取启用层。接口不缓存派生数据。
- `public/timeline-layout.mjs` 根据真实端点、视窗宽度和卡片碰撞分配有限泳道。密集处聚合，选择列表每次展开最多 30 条。地图聚合随屏幕投影与缩放改变。作品和知识的所有权、年代编码与原写入流程沿用 V7。

### 地图地理参照

个人地图复用 `atlas/data.mjs` 的疆界快照、`atlas/place-api.mjs` 的视野查询和缓存，以及 `atlas/geography.mjs` 的自然地理分级图层与标签避让。个人侧的 `map-reference.mjs` 负责非交互参考标签，对个人标记预留空间。政权标签选择当前可见多边形内的锚点，跳过直接跨日期变更线的环形几何。历史地名只用当年有地点记载的结果，优先采用同期名称，资料收录名用点线标记。河流、湖泊和山脉标识为现代参照。参考年变化会清空历史标签，忽略之前的异步地点响应。历史时空原有开关、搜索、详情和事件仍由自身页面维护。

### 结项与技术债

V7/V7.1 功能阶段以源码工作区和隔离资料库验收。首个正式安装版本、正式与开发实例隔离，以及版本晋升见 [正式发行说明](RELEASE.md)。

- 旧版点片段的冗余结束年可继续读取。新版投影和版本化保存以点的起始年为准，保持旧片段的派生标识。底图参考年和个人数据筛选分别处理。
- 两个图层请求各自读取原索引，单次完整查询在共享队列内捕获两份快照。启用知识时仍传输该层全部标注。待真实使用出现瓶颈后，再测量范围分页和地图标记重排；作品整表写入中的粗粒度冲突也留待届时评估。
- 历史参考的政权锚点会省略部分跨日期变更线几何。旧正文版本和无引用附件继续保留，按原备份和恢复约定处理。
- 下一阶段为知识库内部的知识专题，先讨论设计方案，再启动开发。

## 历史时空维护与剩余事项

1. 批量目录和下载账本都在 Git 忽略的 `atlas-data/`。运行顺序和统计口径见 `docs/DATA_SOURCES.md`。Wikidata 的抓取与导入是分开的，抓取重跑复用完好的分片。每次更新 EventKG 或 Wikidata，按文档顺序刷新 QID 合并及 TextEvent 查重。发布检查运行 `node scripts/verify-event-catalog.mjs` 和 `npm test`。事件编辑表单及人工复核工作台尚未实现。
2. 补 WHG 候选：未认证的接口请求返回 403。已登录网页仍会按数据集限制下载，例如 1911 年中国城镇。可联系发布者，或选用已获准独立发布的同源文件。不得用未经核实的坐标补齐缺失文件。
3. 复核 Viabundus 已入库节点的覆盖与地名年代，检查日本 CODH 行政地名变迁表的 ID 对齐。只有可追溯的时间依据能进入年份图层。
4. 继续检查重复：复用来源稳定 ID 和有出处的人工对应关系，保留冲突来源。核对性能后再考虑地理索引优化。

## 操作命令

V6 便携部署见 README。源码开发和演示使用各自独立的默认目录，正式启动必须指定数据目录。服务按实际数据目录的规范路径获取独占的本机监听锁，跨 checkout 和 HTTP 端口生效。锁端口冲突会停止启动，进程退出后系统释放锁。便携路径下的 `logs/state-*.json` 含本机控制凭证，不复制到发布包，不对外共享。重用或停止时先验证一次性挑战的签名、模式和资料库身份。异常退出留下的状态文件不当作活进程依据。

V6 接手时确认了两套旧进程：项目正式资料库和临时示例库使用不同端口和目录。这两套旧进程已停止，正式库已完整备份并逐文件校验。真实库接入便携目录须先确认，保留原始库与备份。地图资料恢复与程序更新分开，未确认再分发许可的数据不用于公开发布。

```powershell
npm ci
npm run atlas:prepare
npm run atlas:places
npm test
npm start
```

- `atlas:prepare -- --with-comparison` 首次获取对照快照；`atlas:prepare -- --refresh-encyclopedia` 联网重建百科关联。
- 用 `npm run atlas:import-places -- lpf <文件> <元数据>` 导入 LPF。Pleiades 使用 `pleiades <官方 JSON 或 gzip>`。
- 数据变更后重启 Chronicle，进程会重新读取索引。先确认旧实例身份和当前端口，再安全停止并复用已确认的可用地址。
- 不记录凭据值、不提交 `.env` 或 `credentials/`。WHG 登录和许可步骤见数据源清单。
