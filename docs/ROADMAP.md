# Chronicle 后续开发路线（Roadmap）

更新：2026-11-28

> **状态：规划备忘，暂缓执行（Deferred / Not approved for implementation）。**
> 本文仅记录讨论结果与候选设计，不是开发指令，不授权创建开发分支、修改程序、迁移数据、部署服务或发布版本。只有用户明确选定范围并启动对应 Issue 后才进入实现。本文不覆盖当前 Issue 的验收条件。

## 1. 产品方向与使用原则

- Chronicle 是持续演进的个人知识与时空管理工具。优先投入日常使用，在实际使用中发现问题、逐步迭代；不设置短期正式发布、便携部署或功能冻结期限。继续以源码工作区使用为主。
- 知识记录用于捕捉碎片，知识专题用于人工组织、关联、补充与系统化理解；保持轻量记录，不要求每条记录立即分类或归入专题。
- 个人知识正文、专题的知识组织与修订由用户亲自完成。AI 可以按需只读审阅、提出错误、矛盾、遗漏与验证建议；不得未经明确授权直接修改知识正文、专题文章或个人资料。软件开发与个人知识写作是两类不同的任务。历史时空的外部资料仍保持独立。
- 保护正式数据优先于界面迭代。保留正式、开发、演示库隔离；继续使用当前 JSON 索引、Markdown 正文及本地附件，按实际需求评估存储技术，不因移动端或主题功能而迁移数据库。
- 正式库备份应覆盖同一一致快照的完整资料目录，验证恢复；避免多个实例同时写入同一资料库。版本冲突、原子写入与现有数据兼容不能因新界面而退化。

## 2. 候选阶段 A：现有 UI 与主题系统

状态：未启动；优先处理实际使用暴露的问题，主题可分批增加。

### UI 收尾

- 知识记录：展开条目与列表中普通条目应有清楚的视觉层级；避免重复标题、关闭态内容冗余。
- 知识专题：返回上一级入口应清晰且易点击；大纲默认可见，不强制展开/收起。检查已有相关 Issue 与实际实现，已修复项不重复开发。
- 标签管理、弹窗关闭、字号、间距及键盘操作等按实际使用体验优化。
- 保留四个顶级模块及知识库内部子板块，不因皮肤增加重复页面或新的业务模块。

### 主题架构（候选）

- 保持一套组件、布局和业务逻辑，多套视觉主题。先审查既有 `public/app-shell.mjs`、共享 `chronicle-theme` 设置和各页 CSS；在其基础上扩展，不创建互不兼容的第二套主题状态。
- 使用 CSS custom properties / design tokens 统一背景、面板、文字、边框、强调色、状态色、字体、圆角、阴影与间距；允许必要的组件级 token。
- 先打磨默认主题，再逐步加入深色研究院、羊皮纸/古籍、博物馆展陈等候选风格。具体配色、字体和纹理由用户后续确认；不要求一次实现全部。
- 外观设置支持跨页面主题切换和持久化；字体、密度、纹理等可按真实需求扩展。地图底图、图层、图例和标注保持可读性。
- 验收：四个顶级页面、知识专题、弹窗、表单、标签、地图与时间轴在各已实现主题下保持可读、可操作；重载与跳转不丢失主题；不改变存储结构或已有业务行为。

## 3. 候选阶段 B：手机端快速知识记录

状态：未启动；日常碎片记录是明确需求，优先于复杂移动端功能。

### 架构

- 多端访问、单一权威数据源。家用电脑上的现有 Node.js HTTP 服务保存正式资料；电脑浏览器与手机浏览器访问同一 API 和同一份资料。家用电脑承担服务器角色，无需另购服务器或立即开发原生 APP。
- 在现有原生 HTML/CSS/ES Modules 架构上做响应式布局，复用后端及写入、版本保护机制。先实现移动 Web；安装式 PWA 与离线能力作为后续增强，避免维护两套独立业务逻辑。
- 第一版重点：快速新建知识、保存 Markdown、阅读、搜索及基本编辑；标题、标签、关联保持可选。完善窄屏导航、编辑器、触控尺寸、软键盘、保存反馈。专题深度编排、地图与复杂管理可暂以桌面端为主。
- 验收：手机创建的记录在电脑刷新后可读；电脑端更新可在手机刷新后可读；重复保存、失效请求、冲突与失败明确反馈；不污染示例或开发库。

## 4. 候选阶段 C：安全远程访问

状态：未启动；方案未确定，需先在隔离测试库验证。这里的个人远程访问与公开部署/发布是不同事项。

- 局域网：先验证手机通过家庭 Wi-Fi 访问指定服务；当前默认回环地址 127.0.0.1，外部访问需要明确配置监听地址与防火墙范围。保持默认仅本机访问。
- 私有网络：评估现有 ZeroTier 等方案，验证手机 VPN 与其他网络应用的兼容性、访问控制及服务地址；不将匿名写入 API 暴露至互联网。
- 可选隧道：Cloudflare Tunnel + Access 等仅作为候选，需核实域名、身份验证、第三方服务依赖、HTTPS、API/静态资源的保护及设备授权；不得把未经认证的服务直接开放。按需要评估会话安全、跨站请求防护、上传与限流、日志和凭据保护。
- 正式库接入须先确认权限、备份、服务身份与实例隔离。电脑关机、休眠或断网时，在线远程访问将不可用；不默认要求电脑全天开机。

## 5. 候选阶段 D：PWA 与离线知识收件箱

状态：未启动；在移动 Web 和安全访问方式明确后再评估。

- 可安装 PWA：评估 HTTPS 安全上下文、manifest、service worker、应用壳缓存与更新策略；不默认缓存完整私有资料或大体积历史地图。共享设备、退出登录与本地数据清理需有明确规则。
- 离线收件箱：第一版仅支持离线新增知识草稿；先可靠写入手机本地 IndexedDB，再在可用连接下提交至正式服务。每条待提交记录使用稳定唯一 ID，由服务端实现幂等创建；服务端确认持久化成功后才标记已同步。
- 展示草稿、待同步、失败、已同步状态，提供手动重试；网络中断、服务端重启、页面关闭、重复请求时不得静默丢失或重复创建记录。浏览器本地存储可能被清理，考虑草稿导出/恢复及明确提示。
- 不依赖所有手机浏览器均支持后台同步；应用打开时重试作为基础路径。已有条目离线编辑、删除、附件同步及双向冲突合并暂不纳入第一版，另行设计。
- 验收：离线录入 → 关闭并重新打开应用 → 恢复连接 → 成功提交 → 电脑可读；重复提交仅生成一条；失败保留草稿且可见；不能用本地草稿覆盖较新的正式数据。

## 6. 执行与排期

- 当前行动：仅保存本规划，继续按既有使用/开发安排；不自动启动 A–D，不自动开启、关闭或分派 Issue。
- 建议顺序：现有 UI 收尾与主题基础、手机快速记录、安全远程访问、离线增强。UI 与移动端优先级可随使用反馈调整；不预先绑定 V8/V9/V10 等版本编号，避免与现有版本及 Issue #8 冲突。
- 每次启动前由用户明确范围，再根据 `AGENTS.md` 形成独立 Issue、核对最新 main 和已有功能、设计验收条件。使用隔离资料库测试，不操作正式数据；未授权不部署、不发布、不合并或关闭 Issue。
- 方案选择仍待确认：首批主题及视觉方案、移动端首版范围、远程网络与身份验证方案、离线实现细节。本文记录的技术路线是讨论候选，不是已实现功能。
